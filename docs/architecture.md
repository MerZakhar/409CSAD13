Архітектура​‍​‌‍​‍‌ AI-агента Build Engineer
1. Призначення
Цей агент існує для того, щоб автоматизувати початкове налаштування кросплатформного проєкту на C++. Він створює вихідний код Hello World, готує систему складання CMake, додає юніт-тестування через GoogleTest, а ще формує CI/CD pipeline у GitHub Actions, щоб код перевірявся на Windows, Linux і macOS.
2. Навички (Skills)
У агента є три основні навички:
* project-scaffold: тут відбувається створення структури C++ проєкту та генерація базового файлу src/main.cpp.
* build-and-test: відповідає за генерацію CMakeLists.txt для складання проєкту та налаштування тестів GoogleTest у папці tests/.
* github-actions: генерує файл .github/workflows/ci.yml, який запускає збірку та тести в GitHub Actions на різних ОС.

3. Команди (Commands)
Запускати агента можна через такі команди:
* git-init: перевіряє, в якому стані перебуває репозиторій, і створює або оновлює правила ігнорування у .gitignore.
* create-project: викликає навичку project-scaffold, щоб створити базу проєкту.
* create-build: запускає навичку build-and-test для генерації CMake конфігурацій і тестів.
* create-actions: ініціює навичку github-actions, аби налаштувати CI.
* check: робить фінальну перевірку, чи присутні всі потрібні файли та чи коректні конфігурації, при цьому код не модифікується.
* init: головний оркестратор, він послідовно викликає всі попередні команди, починаючи з git-init і закінчуючи check.

4. Передача даних між етапами
Проміжні стани агент у пам'яті не зберігає. Дані між кроками передаються через файлову систему. Скажімо, команда create-build очікує, що структуру проєкту вже створено командою create-project, і на основі файлів у папці src/ генерує конфігурації CMake.
5. Обробка помилок оркестратором
Команда init працює як оркестратор і виконує кроки один за одним. Якщо на якомусь етапі, наприклад під час валідації командою check, виявляється, що потрібного файлу немає або в синтаксисі CMakeLists.txt є помилка, процес зупиняється. Агент показує повідомлення про помилку та чекає подальших вказівок від користувача. Він не намагається сам переписувати історію Git і не видаляє наявні ​‍​‌‍​‍‌файли.
