## Передумови

- Працюй лише в корені поточного репозиторію.
- Перевір, чи доступний Git і чи є поточний каталог Git-репозиторієм.
- Не видаляй файли, не змінюй історію та не виконуй `git push --force`.
- Якщо `.gitignore` уже містить несумісні правила або незрозумілий користувацький вміст, не перезаписуй його автоматично.

## Дії

1. Перевір стан репозиторію через `git status`.
2. Якщо Git-репозиторій ще не ініціалізовано, виконай звичайний `git init` без зміни або переписування історії.
3. Перевір кореневий `.gitignore`. Якщо його немає, створи його; якщо він є, доповни лише відсутніми правилами.
4. Забезпеч правила для `build/`, `out/`, об'єктних файлів C++ (`*.o`, `*.obj`, `*.a`, `*.lib`, `*.so`, `*.dll`, `*.exe`) та `.vscode/`.
5. Перевір, що зміни повторно застосовуються без дублювання рядків.

## Очікувані файли

- `.gitignore` у корені проєкту з правилами для `build/`, `out/`, артефактів C++ та `.vscode/`.
- Каталог `.git/` лише якщо репозиторій не був ініціалізований раніше.

## Повідомлення про помилку

Зупини роботу та покажи повний текст помилки, якщо Git недоступний, ініціалізація не вдалася або `.gitignore` неможливо безпечно прочитати чи оновити:

> Помилка git-init: не вдалося підготувати Git-репозиторій або `.gitignore`. Виконання зупинено; наявні файли та історію не перезаписано. Виправте проблему й повторіть команду.
